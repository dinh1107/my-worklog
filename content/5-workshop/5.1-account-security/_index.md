# Securing the AWS Account and Setting Up Cost Controls

In this section, we will secure the AWS root user with multi-factor authentication, select the deployment Region, and create an AWS Budget to monitor the cost of the project.

This is the first step that should be completed before creating resources such as AWS IoT Core, Lambda, DynamoDB, SNS, S3, and EventBridge Scheduler.

## Why is this step necessary?

The AWS root user has full access to all resources, billing information, and security settings in the AWS account. If the root credentials are compromised, an unauthorized person could use resources, modify permissions, or generate unexpected charges.

Therefore, the root user is used in this workshop only to:

- Perform the initial security configuration.
- Enable multi-factor authentication.
- Create an AWS Budget and cost alerts.
- Create the IAM user and initial administrative permissions.
- Perform tasks that require root credentials.

After the initial configuration, the remaining deployment steps will be performed with the IAM user `dinh-fcj`.

## Expected outcomes

After completing this section:

- MFA is enabled for the AWS root user.
- Singapore is selected as the deployment Region.
- A monthly cost budget is available.
- Email cost notifications are configured.
- The root user is no longer used for daily tasks.

## 5.1.1. Sign in as the AWS root user

Open the AWS Management Console sign-in page:

```text
https://console.aws.amazon.com/
```

Select:

```text
Sign in using root user email
```

Enter the email address used to register the AWS account, select **Next**, and enter the root password.



### Verify the result

After signing in, select the account menu in the upper-right corner. The current session should be identified as the **Root user**.



---

## 5.1.2. Open the Security credentials page

From the AWS Management Console navigation bar:

1. Select the account name in the upper-right corner.
2. Select **Security credentials**.
3. Locate the **Multi-factor authentication (MFA)** section.

Navigation path:

```text
Account menu
→ Security credentials
→ Multi-factor authentication (MFA)
```


### Explanation

MFA adds an authentication factor in addition to the account password. During sign-in, the user must provide both:

- The AWS account password.
- A one-time code generated by the MFA device.

If the password is compromised, an attacker will still have difficulty signing in without the registered MFA device.

---

## 5.1.3. Assign an MFA device to the root user

In the **Multi-factor authentication (MFA)** section, select:

```text
Assign MFA device
```

Enter a device name, for example:

```text
Root-MFA
```

Select the following device type:

```text
Authenticator app
```

Then select **Next**.

A TOTP-compatible authenticator application can be used, such as:

- Google Authenticator.
- Microsoft Authenticator.
- Authy.
- A password manager that supports TOTP.



### Scan the QR code

1. Open the authenticator application.
2. Add a new account.
3. Scan the QR code displayed by AWS.
4. The application generates a six-digit code.
5. Enter the current code in **MFA code 1**.
6. Wait for the application to generate a new code.
7. Enter the new code in **MFA code 2**.
8. Select **Add MFA**.



### Verify the result

Return to the **Multi-factor authentication (MFA)** section and verify that the new device appears in the list.

![MFA enabled for the root user](/images/5.1.2.png)

Expected result:

```text
MFA device: Assigned
Device name: Root-MFA
```

The actual device name may differ depending on the configuration used in the account.

---

## 5.1.4. Check the root access keys

On the **Security credentials** page, locate:

```text
Access keys
```

The root user should not have access keys for AWS CLI, SDK, or application access.

Recommended result:

```text
No access keys
```



### Why should root access keys be avoided?

Root access keys provide full programmatic access to the AWS account. If an access key and secret access key are exposed, an attacker could access AWS resources through APIs without signing in to the AWS Console.

This workshop does not require a root access key. Later programmatic access should use an appropriate IAM role, IAM user, or temporary credentials.

## 5.1.5. Select the AWS Region

Open the Region selector in the upper-right corner of the AWS Management Console.

Select:

```text
Asia Pacific (Singapore)
ap-southeast-1
```


### Why is Singapore selected?

The Singapore Region is used consistently throughout the project to:

- Reduce connection latency from Vietnam.
- Prevent resources from being created accidentally in different Regions.
- Keep IoT Core, Lambda, DynamoDB, SNS, S3, and EventBridge configurations consistent.
- Simplify the management of ARNs, IAM policies, and project resources.

Regional project resources will be created in:

```text
ap-southeast-1
```


### Verify the result

The navigation bar should display:

```text
Singapore
```

Verify the selected Region again whenever a new AWS service is opened.

## 5.1.6. Open AWS Billing and Cost Management

Enter the following in the AWS Console search bar:

```text
Billing and Cost Management
```

Open the service and select:

```text
Budgets
```

Navigation path:

```text
AWS Console
→ Billing and Cost Management
→ Budgets
```



### Why is a Budget required?

AWS Budgets tracks actual and forecasted costs. AWS sends a notification to the configured email address when the cost reaches an alert threshold.

A Budget does not automatically stop or delete resources. It provides an early warning when spending is approaching the planned limit unless Budget Actions are configured separately.

---

## 5.1.7. Create a Cost Budget

On the **Budgets** page, select:

```text
Create budget
```

Under **Budget setup**, select:

```text
Customize (advanced)
```

Under **Budget types**, select:

```text
Cost budget
```

Then select **Next**.



### Configure the budget details

Enter the values that match the Budget created in the AWS account.

Example configuration:

| Property | Value |
|---|---|
| Budget name | `SmartHome-Monthly-Budget` |
| Period | `Monthly` |
| Budget renewal type | `Recurring budget` |
| Budgeting method | `Fixed` |
| Budget amount | Enter the project cost limit |
| Budget scope | All AWS services |
| Cost type | Unblended costs or the default configuration |



### Component explanation

- **Budget name:** Identifies the Budget in the AWS account.
- **Period:** Determines how often the Budget is measured and renewed.
- **Recurring budget:** Automatically renews the Budget for each period.
- **Fixed budget:** Uses the same spending limit for every month.
- **Budget amount:** The maximum expected cost for one month.
- **Budget scope:** Defines the services and resources included in the Budget.
- **Unblended costs:** Tracks the actual resource costs charged when they are used.

For this workshop, monitoring the whole account helps detect costs from both project resources and resources accidentally created outside the project.

After completing the configuration, select **Next**.

---

## 5.1.8. Configure cost alerts

On the **Configure alerts** page, select:

```text
Add an alert threshold
```

One or more alert thresholds can be configured. For example:

| Alert | Threshold | Type | Purpose |
|---|---:|---|---|
| Early warning | `80%` | Actual | Sends an alert when actual cost reaches 80% of the Budget |
| Limit warning | `100%` | Forecasted | Sends an alert when AWS forecasts that the Budget will be exceeded |

Under **Email recipients**, enter the email address that will receive notifications.



### Actual and Forecasted alerts

- **Actual:** Evaluates the cost that has already been incurred.
- **Forecasted:** Evaluates the estimated cost at the end of the Budget period.

A Forecasted alert can identify a potential Budget overrun before the entire cost has been incurred.

The following feature is not configured in this workshop:

```text
Budget Actions
```

Therefore, reaching a threshold only sends a notification. It does not automatically stop AWS services.

After configuring the alerts, select **Next**.

---

## 5.1.9. Review and create the Budget

On the review page, verify:

- The Budget name is correct.
- The period is `Monthly`.
- The Budget type is `Cost budget`.
- The Budget amount matches the project plan.
- The alert thresholds are configured.
- The notification email address is correct.

Select:

```text
Create budget
```



After the Budget is created, it appears in the Budget list.

![Budget created successfully](/images/5.1.6.png)

### Verify the result

Open the Budget details and verify:

```text
Budget status: Active
Budget type: Cost
Period: Monthly
Alerts: Configured
```

The displayed field names may vary slightly depending on the current AWS Console interface.
