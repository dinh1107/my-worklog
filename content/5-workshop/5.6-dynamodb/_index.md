# Creating the Amazon DynamoDB Table

In this section, we will create the `SmartHomeTelemetry` table to store smart home telemetry and event data.

DynamoDB is selected because it is a serverless NoSQL database suitable for JSON-based IoT data and does not require database server management.

## Role of DynamoDB

The `SmartHomeTelemetry` table stores:

- Temperature and humidity data.
- Raw gas sensor ADC values.
- Device states.
- Gas warning events.
- Incorrect-password events.
- Record creation and expiration times.

The `SmartHomeIngest` Lambda function will later write data to this table automatically.

## Objectives

After completing this section:

- The `SmartHomeTelemetry` table is created.
- A partition key and sort key are configured.
- The table uses On-demand capacity.
- Time To Live is enabled with `expiresAt`.
- Stored data can be inspected through Explore table items.

## 5.6.2. Configure the table

Enter:

| Property | Value |
|---|---|
| Table name | `SmartHomeTelemetry` |
| Partition key | `deviceKey` |
| Partition key type | `String` |
| Sort key | `recordKey` |
| Sort key type | `String` |

![Configure the SmartHomeTelemetry table](/images/5.6.2.png)

### Primary key explanation

The table uses a composite primary key.

#### Partition key: `deviceKey`

`deviceKey` groups records belonging to the same device.

For example:

```text
home01#esp32-01
```

Records with the same `deviceKey` can be queried using the same device identifier.

#### Sort key: `recordKey`

`recordKey` uniquely identifies and orders device records by data type, timestamp, or message identifier.

The exact `recordKey` value will be generated by the `SmartHomeIngest` Lambda function in section 5.8.

The composite key supports:

- Multiple records for one device.
- Device-based queries.
- Time-based ordering.
- Separation of telemetry and events.
- Prevention of unintended overwrites.

## 5.6.3. Select the capacity mode

Under **Table settings**, select **Customize settings** if the complete configuration is not displayed.

Configure:

| Property | Value |
|---|---|
| Table class | `DynamoDB Standard` |
| Capacity mode | `On-demand` |
| Encryption | `AWS owned key` |
| Deletion protection | `Enabled` |

### Why use On-demand?

On-demand capacity is suitable for this workshop because:

- Read Capacity Units do not need to be configured.
- Write Capacity Units do not need to be configured.
- Capacity automatically adjusts to the number of requests.
- It supports variable IoT traffic.
- It is convenient for small projects and test environments.

Deletion protection helps prevent accidental table deletion. It must be disabled before deleting the table during resource cleanup.

After reviewing the configuration, select:

```text
Create table
```

## 5.6.5. Enable Time To Live

Open:

```text
SmartHomeTelemetry
```

Then select:

```text
Additional settings
→ Time to Live (TTL)
→ Turn on
```

Enter the TTL attribute:

```text
expiresAt
```

Confirm the configuration.

![TTL enabled with the expiresAt attribute](/images/5.6.5.png)

### How does TTL work?

The `expiresAt` attribute stores the record expiration time as:

```text
Unix epoch time in seconds
```

For example:

```text
1799967600
```

The DynamoDB data type must be:

```text
Number
```

Do not use:

- An ISO date-time string.
- The String data type.
- Unix epoch time in milliseconds.

The `SmartHomeIngest` Lambda function calculates and adds `expiresAt` when it writes a record.

DynamoDB automatically deletes expired records without consuming write throughput for the deletion in the original Region.

> TTL does not delete a record at the exact expiration time. The item can remain for several days before DynamoDB removes it.

The TTL attribute name is case-sensitive and must be exactly:

```text
expiresAt
```

## 5.6.6. Inspect stored data

After the Lambda function and AWS IoT Rules are completed in the following sections, open:

```text
DynamoDB
→ Tables
→ SmartHomeTelemetry
→ Explore table items
```

Select:

```text
Run
```

The table should display telemetry and event records.

![Data stored in SmartHomeTelemetry](/images/5.6.6.png)

### Attributes to inspect

| Attribute | Purpose |
|---|---|
| `deviceKey` | Identifies the device |
| `recordKey` | Uniquely identifies and orders the record |
| `messageId` | Identifies a message and supports deduplication |
| `recordType` | Distinguishes telemetry from events |
| `timestamp` | Time when the message was created |
| `expiresAt` | Record expiration time |
| Sensor data | Temperature, humidity, and gas ADC |
| Device states | Door, light, or fan state |
| Event type | Alert event category |

Some attribute names might differ depending on the deployed Lambda source code.

Before publishing the screenshot, verify that the stored data does not contain:

- Door passwords.
- Personal email addresses.
- Access keys or secret keys.
- Certificates or private keys.
- Other authentication information.
